# 站内搜索

站内搜索为网站目录和用户公开收藏提供统一入口，目标是让访客不必先进入分类目录也能快速找到站点。

## 访问方式

- 独立页面：`/search`
- 首页搜索框：切换到「站内搜索」后回车
- 页面支持关键词、类型、分类、排序和分页，结果关键词会高亮

## 当前实现

当前版本使用 MariaDB `LIKE` 查询作为搜索后端，接口契约按 Meilisearch 方案设计，后续切换索引实现时不需要改动前端。

- `GET /api/search`：搜索目录站点与公开收藏
- `GET /api/search/suggest`：即时联想与热门搜索词
- `POST /api/search/click`：记录搜索结果点击，用于计算点击率
- `GET /api/admin/search-index`：查看索引状态
- `POST /api/admin/search-index`：全量重建拼音索引

目录站点只返回 `status = 'published'` 且 `health_hidden = 0` 的记录；公开收藏只返回 `user_links.is_public = 1` 的记录。

## 匹配与排序

- 名称、标题、简介、关键词、域名均参与匹配
- 多个关键词之间是 AND 关系
- 中文使用 MariaDB 排序规则做不区分大小写的匹配
- 英文和数字直接匹配名称、关键词与域名
- 拼音全拼和首字母通过 `pinyin-pro` 生成内存别名，例如「百度」「baidu」「bd」可命中同一条目
- 相关度优先级：名称精确匹配、名称前缀、拼音别名、标题、关键词、简介
- 其他排序：最新收录、名称排序
- 精选站点在同等相关度下优先展示

## 拼音索引

拼音别名不落库，服务启动后按需构建，并在内存中缓存：

- 缓存有效期 5 分钟
- 目录增删改会通过 `directory_cache_version` 失效缓存
- 多实例部署下，其他实例最多延迟约 15 秒感知变更
- 后台「搜索分析」页面可以查看索引状态并触发全量重建

当前数据量下，内存索引可以覆盖全部已发布目录站点。数据量增长到十万级后应切换到 Meilisearch。

## 搜索分析

站内搜索事件写入 `search_events`：

- `engine = 'site'`
- `kind = 'input'`：搜索请求，记录结果数与耗时
- `kind = 'result_click'`：结果点击
- `results`：结果总数
- `took_ms`：服务端搜索耗时

后台「搜索分析」页面展示站内搜索次数、结果点击、点击率、平均耗时、P95、峰值耗时、零结果词和每日趋势。

首次部署本功能后需要执行迁移：

```bash
node scripts/migrate.mjs
```

## 降级与限制

- 搜索与联想接口均有限流
- 单页最多返回 40 条，最多翻到第 50 页
- 深分页最多合并前 500 条目录与收藏结果，超出时页面提示结果可能不完整
- 数据库不可用时接口返回错误，前端展示重试入口
- 当前版本不做全网爬虫、独立网页索引或 AI 问答

## 后续 Meilisearch 方案

路线图中的下一阶段会将目录、公开收藏写入 Meilisearch 单节点，并保持现有接口不变：

- Meilisearch 只监听 `127.0.0.1`
- Nuxt 服务端代理搜索请求，浏览器不直接访问 Meilisearch
- 目录变更触发增量同步
- 每日低峰全量重建，失败时继续使用旧索引
- 搜索超时或索引不可用时回退到 MariaDB 查询
